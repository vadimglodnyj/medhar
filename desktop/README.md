# Desktop Medhar (Windows)

Власне вікно (Edge WebView2 через **pywebview**) + локальний Flask. Колегам роздаєте один файл **`Install.exe`**.

## Що отримує користувач

| Файл | Призначення |
|------|-------------|
| `Install.exe` | Інсталятор (Inno Setup) |
| `Medhar.exe` | Програма в `Program Files\Medhar\` |
| Ярлик **Medhar** | На робочому столі (опція при встановленні) |

Дані (Excel, SQLite, `.env`, медіа) зберігаються в:

`%LOCALAPPDATA%\Medhar\`

(не в Program Files — можна писати без прав адміна).

## Вимоги на машині колеги

- Windows 10/11 x64
- [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) (на більшості ПК уже є)
- Інтернет (Dropbox / Gemini)

## Збірка у себе

1. Встановіть [Inno Setup 6 або 7](https://jrsoftware.org/isinfo.php) (non-commercial OK).
2. У корені репозиторію:

```powershell
.\desktop\build.ps1
```

Або вручну в Inno Setup Compiler: **File → Open** → `desktop\installer.iss` → **Build → Compile** (спочатку має існувати `dist\Medhar\Medhar.exe` від PyInstaller).

3. Артефакти:
   - `dist\Medhar\Medhar.exe` — для локальної перевірки
   - `dist\Install.exe` — **це роздаєте колегам**

## Режим команди (PIN)

Секрети Turso / Gemini / Dropbox / WhatsApp **не** правляться колегами в `.env`.
Адміністратор один раз збирає зашифрований пакет:

```powershell
# PIN — спільний на всю команду (мінімум 4 символи). Не комітьте його в git.
$env:MEDHAR_TEAM_PIN = "ВАШ_PIN"
.\desktop\build.ps1
```

Або окремо:

```powershell
.\venv\Scripts\python.exe .\scripts\build_team_vault.py --env .env --pin "ВАШ_PIN"
```

У `Install.exe` потрапляє `data/team.vault`. На першому запуску колега обирає:

- **Локально** — лише характеристики на цьому ПК;
- **Команда** + PIN — спільний журнал, Excel у Dropbox, Gemini, Dropbox API і WhatsApp API.

Вибір зберігається в `%LOCALAPPDATA%\Medhar\session.json`. Змінити режим:
пункт меню «Команда» / «Локально».

Шлях Excel шукається автоматично: `Dropbox\Програми\patientss\data`
(літера диска не важлива). Потрібен встановлений клієнт Dropbox.

### Офлайн-режим амбулаторного журналу (режим «Команда»)

У режимі команди журнал і картотека **завжди пишуться локально**
(`%LOCALAPPDATA%\Medhar\data\outpatient_journal.db`). Turso — спільна хмарна
копія; коли є інтернет, фоновий sync підтягує чужі зміни і відправляє ваші.

- **Офлайн**: додавайте/редагуйте звернення як зазвичай; зміни в черзі outbox.
- **Онлайн**: синхронізація кожні ~45 с або по кліку на індикатор **Онлайн/Офлайн**
  у верхньому меню (жовтий badge — скільки записів чекає відправки).
- **Конфлікти**: last-write-wins за часом `updated_at` (без діалогів).

Медіа: файли зберігаються локально; у Dropbox відправляються після появи мережі.

### Дев-режим (без перевстановлення)

```powershell
.\desktop\dev.ps1            # браузер, автоперезапуск при зміні .py
.\desktop\dev.ps1 -Window    # те саме, але у вікні програми
```

Працює з тими самими даними і `.env`, що й встановлена програма
(`%LOCALAPPDATA%\Medhar\`), але на порті **17655** — тож встановлений Medhar
може працювати одночасно на своєму 17654.

| | Браузер (за замовчуванням) | `-Window` |
|---|---|---|
| Зміни в `.py` | сервер перезапускається сам | треба перезапустити скрипт |
| Зміни в шаблонах / CSS / JS | оновити сторінку (F5) | оновити сторінку |
| Traceback помилки | у браузері | у вікні |

Перезбирати `Install.exe` потрібно лише коли роздаєте нову версію колегам.

## Оновлення вже встановленої програми

Той самий `Install.exe` можна запускати поверх старої установки (однаковий `AppId`).
Дані в `%LOCALAPPDATA%\Medhar\` **не** затираються.

Оновлення для команди йде через **Dropbox** (`Програми/patientss/releases/`):

1. `.\desktop\build.ps1` викладає туди `Install.exe` і `update_manifest.json`.
2. У колег із синхронізованим Dropbox з’являється банер → **Оновити** (файл береться з локальної папки `releases`).
3. Shared link не потрібен. У Dropbox App Console бажано також увімкнути scope **`files.content.read`**, якщо хтось без локального sync.

Щоб пропустити публікацію під час збірки: `$env:MEDHAR_SKIP_UPDATE_PUBLISH = "1"`.

Звичайний `python app.py` як і раніше працює з папки проєкту.

## Перший запуск у колег

1. Відкрити `Install.exe`.
2. Якщо SmartScreen: **Додаткові відомості** → **Виконати все одно**.
3. Встановити, запустити **Medhar**.
4. Якщо працюєте **локально**, за потреби заповнити `%LOCALAPPDATA%\Medhar\.env`
   (напр. власні Gemini / Dropbox / WhatsApp credentials для розробки) — шаблон
   створюється автоматично.
5. На сторінці «Бази даних» завантажити `treatments_*.xlsx` / `base.xlsx` / `rkch.xlsx`.

У режимі команди секрети пакуються в `data/team.vault` і відкриваються PIN-кодом.
У локальному режимі секрети з `.env` нікуди не пакуються.

## WhatsApp Business API

Medhar може вручну надсилати зі сторінки лікування:
- згенерований `Текст для WhatsApp`,
- прикріплені image / pdf медіа,
- на один номер лікаря/адміністратора.

Для цього потрібні:

```env
WHATSAPP_ACCESS_TOKEN=EA...
WHATSAPP_PHONE_NUMBER_ID=123456789012345
WHATSAPP_RECIPIENT=380XXXXXXXXX
WHATSAPP_API_VERSION=v20.0
```

Рекомендовано додавати їх у `team.vault`, а не роздавати окремими `.env`.

## Спільні Excel через Dropbox

SQLite-файл журналу не можна класти у Dropbox: одночасний запис із кількох ПК
створює конфліктні копії та може пошкодити БД. Через Dropbox спільними робимо
лише Excel:

1. Власник папки створює `D:\Dropbox\Програми\patientss\data`.
2. Копіює туди `rkch.xlsx`, `base.xlsx` і `treatments_YYYY.xlsx`.
3. Людині, яка оновлює бази, дає **Can edit**, решті — **Can view**.
4. На кожному ПК із Dropbox у `%LOCALAPPDATA%\Medhar\.env` задає шлях:

```env
MEDHAR_EXCEL_DIR=D:\Dropbox\Програми\patientss\data
```

Логін або Dropbox API-токен для читання цих Excel не потрібен — їх синхронізує
клієнт Dropbox для Windows. Якщо `MEDHAR_EXCEL_DIR` порожній, програма працює
з локальними Excel у `%LOCALAPPDATA%\Medhar\data`, як раніше.

Оновлювати спільні Excel має одна людина. Не відкривайте той самий файл на
запис із двох ПК одночасно.

## Спільний амбулаторний журнал у Turso

Для командного режиму створіть безкоштовну БД у [Turso](https://turso.tech/) і
додайте на кожному ПК команди однакові реквізити:

```env
TURSO_DATABASE_URL=libsql://your-db-your-org.turso.io
TURSO_AUTH_TOKEN=your-token
```

Обидва поля порожні — локальний SQLite. Якщо задане лише одне поле, Medhar
зупиниться з помилкою конфігурації, щоб випадково не записувати дані локально.
Токен є секретом: не надсилайте `.env` стороннім і не додавайте його в Git.

### Одноразова міграція наявного журналу

Перед першим командним запуском закрийте Medhar, задайте Turso-реквізити у
кореневому `.env` і з репозиторію виконайте:

```powershell
.\venv\Scripts\python.exe .\scripts\migrate_outpatient_to_turso.py `
  --source "$env:LOCALAPPDATA\Medhar\data\outpatient_journal.db"
```

Скрипт переносить журнал, картки, лікування, обмеження і метадані медіа лише
в **порожню** Turso DB. Якщо там уже є дані, він безпечно зупиняється.

## Антивірус / SmartScreen

Без платного **code signing** сертифіката Windows часто попереджає про «невідомого видавця». Це нормально для внутрішнього ПЗ підрозділу.

Що вже зроблено для зменшення блокувань:

- стандартний інсталятор Inno Setup;
- PyInstaller **onedir** (не один величезний onefile);
- без UPX.

Після кількох установок репутація файлу в Defender зазвичай покращується. Для повного зняття попереджень потрібен Authenticode-сертифікат і `signtool` (окремо, платно).

## Оновлення

Зібрати новий `Install.exe` і передати колегам. При встановленні поверх старої версії дані в AppData зберігаються.

### Ярлик показує стару іконку

Explorer кешує іконку за шляхом до файлу, тому після перевстановлення ярлик
іноді лишається зі старою картинкою. Інсталятор бере іконку з окремого
`{app}\medhar.ico` і скидає кеш через `ie4uinit.exe -show`. Якщо стара іконка
все одно лишилась, видаліть ярлик з робочого столу і встановіть ще раз або
скиньте кеш вручну:

```powershell
ie4uinit.exe -show
```
